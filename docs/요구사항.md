# 작은도서관 보조금 증빙 PDF 합치기 도구 — 요구사항

## 1. 목적
평택시 사립작은도서관 운영자가 보탬e에 집행내역을 등록할 때, **집행 1건의 증빙서류(사진·PDF)를 정해진 순서대로 PDF 한 파일로 합치는** 웹 도구.
- 집행 유형(세목)을 고르면 필요한 서류 목록이 체크리스트로 나오고, 칸마다 파일을 넣으면 순서대로 합쳐진다.
- 필수서류가 빠지면 저장 전에 알려 준다.

## 2. 사용자와 환경
- 사용자: 작은도서관 운영자(60대 포함, 컴퓨터 비전문가). 설치·회원가입 없이 **주소만 열면 바로 사용**.
- 기기: 주로 Windows PC(크롬·엣지·웨일). 스마트폰(안드로이드·아이폰)에서도 사용 가능해야 함(사진을 폰으로 찍는 경우가 많음).
- 언어: 한국어만.

## 3. 배포·기술 조건
- **GitHub 저장소 + GitHub Pages**로 배포하는 정적 웹페이지(HTML/CSS/JS). 서버·데이터베이스 없음.
- **모든 처리는 사용자 브라우저 안에서만** 한다. 파일을 어디에도 업로드하지 않는다(강사 신분증·통장사본 등 개인정보가 들어감). 화면에 "파일은 내 컴퓨터 밖으로 나가지 않습니다" 문구 표시.
- 외부 서비스·분석 도구(구글 애널리틱스 등) 넣지 않는다.
- 라이브러리는 CDN 또는 저장소에 포함해 사용. 예: PDF 합치기 `pdf-lib`, PDF 미리보기 `pdf.js`, 아이폰 사진 변환 `heic2any`.
- 빌드 과정 없이 동작하면 가장 좋음(유지보수 쉬움). 필요하면 GitHub Actions로 자동 배포.
- 유형별 서류 목록은 **별도 설정 파일(JSON)**로 분리해서, 코드를 몰라도 매년 매뉴얼이 바뀌면 그 파일만 고칠 수 있게 한다.

## 4. 화면 흐름 (단계형)

### 1단계: 사업 선택
- 작은도서관 우수도서관 육성 / 독서환경 조성 / 독서문화프로그램 지원 / 아이돌봄 독서문화프로그램 / 냉난방비 지원
- 사업에 따라 고를 수 있는 유형만 다음 단계에 보이게 한다(아래 6절 표의 '사업' 열).

### 2단계: 집행 유형(세목) 선택
- 강사료, 원천세, 재료비, 간식비, 도서 구입 등 카드형 버튼으로 표시.
- 각 카드에 보탬e에 넣을 **보조세목 이름**을 함께 표시(예: 강사료 → 행사운영비).

### 3단계: 집행 정보 입력 (선택 입력)
- 집행일, 금액, 거래처(또는 내용) — 파일 이름 자동 생성에만 사용.
- 비워도 진행 가능.

### 4단계: 서류 넣기 (핵심 화면)
- 선택한 유형의 서류 목록이 **순서대로 칸**으로 나열됨. 각 칸에 [필수] / [해당 시] 표시.
- 칸마다 파일 끌어다 놓기 또는 [파일 선택] 버튼. 폰에서는 [사진 찍기]도 가능.
- 한 칸에 여러 파일 가능(예: 강의확인서 4회분).
- 넣은 파일은 작은 미리보기(썸네일)로 표시, 각 장에 **순서 바꾸기(드래그 또는 ↑↓)·회전·삭제** 버튼.
- 칸 옆에 짧은 도움말(예: "사진은 포장을 뜯은 상태로, 품목이 모두 보이게").
- 목록에 없는 서류를 넣을 수 있는 [기타 서류] 칸을 맨 아래에 둔다.

### 5단계: 확인 및 저장
- 필수 칸이 비어 있으면 빨간색으로 표시하고 "OO 서류가 없습니다. 그래도 저장할까요?" 확인창.
- [PDF로 저장] → 파일 다운로드.
- 저장 후 안내: "보탬e 첨부란에 이 파일 하나만 올려 주세요(기본서류/증빙서류 칸 구분 없이 한 곳에)."
- [새 집행 시작] 버튼(같은 사업·유형 유지 옵션).

## 5. PDF 생성 규칙
- 순서: 서류 목록 순서 → 칸 안에서는 사용자가 정한 순서.
- 지원 파일: JPG, PNG, HEIC(아이폰), PDF(여러 쪽이면 전체 포함). 그 외(HWP, 엑셀 등)는 "PDF로 저장한 뒤 넣어 주세요" 안내.
- 이미지는 A4 세로 한 장에 비율 유지해서 맞춤(가로 사진은 자동으로 A4 가로 또는 회전 선택). 휴대폰 사진 방향(EXIF) 자동 보정.
- 용량: 사진은 자동 압축(가독성 유지). 저장 전 예상 용량 표시. 보탬e 첨부 용량 제한 확인 후 초과 시 경고 (※ 한도는 담당자가 확인해서 설정 파일에 입력).
- 파일 이름 자동: `집행일_유형_거래처_금액.pdf` (예: `20261028_강사료_재봉틀수업_364800.pdf`). 입력이 없으면 `유형_저장일시.pdf`. 저장 전에 이름 수정 가능.
- 표지·구분 페이지는 넣지 않는다(실제 증빙만).

## 7. 화면·사용성
- 큰 글씨(기본 18px 이상), 버튼 크게, 한 화면에 한 단계.
- 상단에 진행 단계 표시(① 사업 → ② 유형 → ③ 정보 → ④ 서류 → ⑤ 저장).
- 첫 화면에 "사용 방법" 3줄 안내와 [처음 쓰는 분 보기] 도움말.
- 모바일 화면 대응(세로 화면에서 칸이 한 줄씩).
- 하단에 "평택시립 안중도서관 작은도서관 담당 / 문의 031-xxx-xxxx" (번호는 설정 파일에서 입력).
- 새로고침·창 닫기 시 넣은 파일이 사라진다는 경고.

## 8. 하지 않을 것
- 로그인, 서버 저장, 보탬e 자동 업로드, OCR·서류 자동 판별.
- 넣은 파일을 브라우저 저장소에 보관하지 않음(개인정보).

## 9. 저장소 구성·문서
- `index.html`, `app.js`, `style.css`, `config/docs-2026.json`(유형별 서류), `lib/`(라이브러리), `README.md`.
- README에 ① 사용 주소 ② GitHub Pages 켜는 방법 ③ **매년 서류 목록 고치는 방법**(JSON 어디를 바꾸면 되는지) ④ 문의처를 쉬운 말로.
- 저장소 이름 예: `smalllibrary-pdf` → 주소 `https://<계정>.github.io/smalllibrary-pdf/`.

## 10. 확인 시나리오 (완료 기준)
1. 우수육성 → 강사료 선택 → 9개 칸이 순서대로 나온다.
2. 휴대폰 사진(JPG 세로·가로, 아이폰 HEIC) + 여러 쪽 PDF를 섞어 넣고 순서를 바꿔 저장 → 순서대로, 방향이 바르게 A4로 합쳐진다.
3. 필수 칸 하나를 비우고 저장 → 경고가 뜬다.
4. 사진 30장 넣어도 브라우저가 멈추지 않고, 용량이 표시된다.
5. 개발자도구 네트워크 탭에서 파일 전송이 일어나지 않는다.
6. 스마트폰 크롬·사파리에서 사진 찍기→저장까지 된다.
7. JSON에서 서류 하나를 추가하면 화면에 바로 반영된다.

## 11. 다음에 추가하면 좋은 것 (선택)
- 서식 내려받기 링크(지출결의서·강사수당청구서·강의확인서·봉사일지 HWP).
- 유형별 예시 PDF 보기 링크(개인정보 가린 예시).
- 여러 집행 건을 연속으로 만들 때 마지막 선택 기억(사업·유형만, 파일은 제외).
